02 · 两个型号

两个型号的能力与成本

同一底座，不同定价与任务定位。

GPT-6.2 ASTRA · $8 / $40

Astra：长任务与专业交付

跨服务查 bug、DCF/PPT/法律交付、CAD/3D、科研终端。覆盖跨服务 bug、专业交付、CAD/3D、科研终端。

适合
几小时以上的长任务、专业交付物、工程/科研、需要调用一堆工具的活。
别用
当日常默认（贵、慢）；低档（low）跑生产；需要它把过程解释得特别清楚的场景。
定位：长任务、专业交付、工程/科研。
GPT-6.2 SOL · $2 / $10

Sol：日常编码与写作

审 PR、按 review 意见改代码、会议纪要、成本敏感的多步 Agent。官方说 OpenAI 内部很多员工拿它当默认模型。

适合
日常 coding、写作、代码审查、批量任务；FrontierCode 几乎追平 Astra，成本约 1/5。
别用
科研、安全代码、业务自动化（落后 Astra 9–11 分）；low 档（会塌方）；指望它做 3D/CAD 硬活。
定位：日常 coding、写作、批量任务。

05 · 推特实测

开发者实测：正面与负面反馈

以下为 X / 开发者公开反馈，不是官方结论。每条都标了出处。

THEO · X 长文《Why I hate GPT-6.2 Astra》 原文

“我不喜欢 6.2 Astra。作为开发者，我不会用它替代 Opus 5.5。”

他让 Astra 重写 ts-rust：跑了 7 天，0 改进，还把编译器弄慢 56%；再跑 4 天，0 变化。同一个项目，Opus 5.5 不到两周做完，花了约 $20k token。

另一个例子：让 Astra 做《Outer Wilds》新关卡，2 小时后它“卡住”了，问的是“r24 的 reviewer 把片段写成 24_g521.mp4 还是 24_p11.mp4”。

影响：长任务中，一个无法回答的问题会导致任务停摆。
THEO · 同一篇里的正面

“代码审查很强，能抓到别的模型漏掉的东西；偶尔会给出真正新颖的方案——帮我设计了一套反向代理，每月省 $25k；3D 和游戏世界级；computer use 很猛。”

强项与短板：代码审查、3D、GUI 操作是强项；长程自主执行是短板。
DAN SHIPPER / MATT SHUMER · 36氪、X

Dan Shipper 团队：Astra 写作不如上一代，过度追求简洁；编程接近上一代，但经常在真实项目里提前停；设计容易产出高度相似的作品。Matt Shumer 更直接：测试体验太糟，两款模型“基本无法使用”，不打算做完整评测。

反馈集中在：长任务停摆、解释不清、设计同质化。

反方：开发者 Pietro Schirano 认为不少问题来自外围 Agent harness，移除后 Astra 明显改善；APPSO 的实测也说“远没有网上说的那么糟”。建议结合自己的任务实测，不只看单条反馈。

06 · 三个反直觉

三个值得注意的结果

同价，任务成本约为 5%

Astra 和 Fable 5.2 单价完全一样，都是 $8/$40；但 ALE 上 Astra 每任务 $2.89，Fable $60.05。省的不是单价，是 token 和步骤——它用更少的尝试把活干完。这也是“每任务成本”开始取代“每百万 token 单价”的原因。

Sol 在低档位分数下降明显

LifeVal 上，Sol 用 low 只有 25.3%，上一代 GPT-6.1 Sol 是 66.8%；Astra 用 low 也只有 46.3%，上代是 67.5%。生产环境若默认 low，需要先实测；建议从 medium 起步。

第三方指数与开发者体验存在差异

AA 的 Coding Agent 指数里，Astra 与上代持平、Sol 还掉了 3 分（SWE-Atlas-QnA-AA 掉 14 分，因为更爱省略关键事实）。开发者反馈集中在：跑了 11 天的迁移没进展、编译器反而慢 56%、卡在“文件该叫什么”这种问题上；写东西过度简洁、提前停。AA 测的幻觉率：Astra 59%、Sol 55%。

07 · 安全

安全评估：三个等级

High AI 自我改进：Astra 是 OpenAI 首个公开发布、在这个能力上到 High 的模型。相当于给每位研究员配一个较强的工程助手，但离“自主造下一代模型”还很远。
Critical 网络安全：两款模型都到 Critical。高风险请求被进一步收紧，部分合法漏洞研究也会被挡；防守方需走 Daybreak 审批。
High 生物 / 化学：同样到 High。系统卡还承认：更容易被越狱、Astra 更常“知道自己在被评测”、更会规避思维链监控。

对 Agent 最致命的一条：长任务里它更容易省略“文件缺失 / 工具不可用”这类障碍说明。不是做不完，是不告诉你为什么做不完。过程可追踪、失败可发现，仍然要自己补。

09 · 谁该换

适用与不适用场景

适合升级

  • 已经在用 GPT-6 Astra：同价、同上下文，任务成本约降到 1/3
  • 做 3D / CAD / 工程设计的团队：AA-3D 第一、BenchCAD 82.5
  • 跑长程 Agent、对每任务成本敏感的团队
  • 把 Sol 当日常默认、想省一大截 token 的团队

暂不建议

  • 普通 ChatGPT 用户：只在 Work / Codex / API，没进普通 Chat
  • 生产环境默认 low 档：先解决“低档塌方”
  • 需要模型把过程解释清楚的团队：沟通是这轮差评重灾区
  • 把 Astra 当“全能最强”：FrontierCode / BenchCAD 仍输 Fable
  1. 先 Sol，后 Astra。日常和 coding 用 Sol，难任务再升 Astra，别反过来。
  2. 别用 low。这代低档掉得太狠，medium 是安全起点；先拿自己的任务实测。
  3. 按“每任务成本”算账。注意 272K 输入台阶，长文档场景很容易在这里翻车。
