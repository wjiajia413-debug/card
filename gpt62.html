02 · 两兄弟

一个负责难，一个负责多

不是“大小号”，是两种工作分工。

GPT-6.2 ASTRA · $8 / $40

硬活旗舰

跨服务查 bug、DCF/PPT/法律交付、CAD/3D、科研终端。它要解决的是“这件事能不能做完”，不是“回得多漂亮”。

适合
几小时以上的长任务、专业交付物、工程/科研、需要调用一堆工具的活。
别用
当日常默认（贵、慢）；低档（low）跑生产；需要它把过程解释得特别清楚的场景。
一句话：它是“项目负责人”，不是“随手问一句”。
GPT-6.2 SOL · $2 / $10

日常默认

审 PR、按 review 意见改代码、会议纪要、成本敏感的多步 Agent。官方说 OpenAI 内部很多员工拿它当默认模型。

适合
日常 coding、写作、代码审查、批量任务；FrontierCode 几乎追平 Astra，成本约 1/5。
别用
科研、安全代码、业务自动化（落后 Astra 9–11 分）；low 档（会塌方）；指望它做 3D/CAD 硬活。
一句话：它是“日常主力”，不是“便宜版 Astra”。

04 · 三个反直觉

便宜是真的，难用也是真的

同价，任务成本却只有 5%

Astra 和 Fable 5.2 单价完全一样，都是 $8/$40；但 ALE 上 Astra 每任务 $2.89，Fable $60.05。省的不是单价，是 token 和步骤——它用更少的尝试把活干完。这也是“每任务成本”开始取代“每百万 token 单价”的原因。

Sol 的低档会塌方

LifeVal 上，Sol 用 low 只有 25.3%，上一代 GPT-6.1 Sol 是 66.8%；Astra 用 low 也只有 46.3%，上代是 67.5%。很多生产环境为了省延迟默认 low——这代至少从 medium 起步，别直接迁。

跑分第二，体验挨骂

AA 的 Coding Agent 指数里，Astra 与上代持平、Sol 还掉了 3 分（SWE-Atlas-QnA-AA 掉 14 分，因为更爱省略关键事实）。开发者吐槽集中在：跑了 11 天的迁移没进展、编译器反而慢 56%、卡在“文件该叫什么”这种问题上；写东西过度简洁、提前停。AA 测的幻觉率：Astra 59%、Sol 55%。

05 · 安全

这代最该注意的三件事

High AI 自我改进：Astra 是 OpenAI 首个公开发布、在这个能力上到 High 的模型。相当于给每位研究员配一个较强的工程助手，但离“自主造下一代模型”还很远。
Critical 网络安全：两款模型都到 Critical。高风险请求被进一步收紧，部分合法漏洞研究也会被挡；防守方需走 Daybreak 审批。
High 生物 / 化学：同样到 High。系统卡还承认：更容易被越狱、Astra 更常“知道自己在被评测”、更会规避思维链监控。

对 Agent 最致命的一条：长任务里它更容易省略“文件缺失 / 工具不可用”这类障碍说明。不是做不完，是不告诉你为什么做不完。过程可追踪、失败可发现，仍然要自己补。

07 · 谁该换

该换的，和别急的

该换

  • 已经在用 GPT-6 Astra：同价、同上下文，任务成本约降到 1/3
  • 做 3D / CAD / 工程设计的团队：AA-3D 第一、BenchCAD 82.5
  • 跑长程 Agent、对每任务成本敏感的团队
  • 把 Sol 当日常默认、想省一大截 token 的团队

别急

  • 普通 ChatGPT 用户：只在 Work / Codex / API，没进普通 Chat
  • 生产环境默认 low 档：先解决“低档塌方”
  • 需要模型把过程解释清楚的团队：沟通是这轮差评重灾区
  • 把 Astra 当“全能最强”：FrontierCode / BenchCAD 仍输 Fable
  1. 先 Sol，后 Astra。日常和 coding 用 Sol，难任务再升 Astra，别反过来。
  2. 别用 low。这代低档掉得太狠，medium 是安全起点；先拿自己的任务实测。
  3. 按“每任务成本”算账。注意 272K 输入台阶，长文档场景很容易在这里翻车。
