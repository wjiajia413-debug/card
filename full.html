01

30 秒版

五个判断，够你做“要不要用、怎么用”的决定。

强在哪
长活不是聊天

SWE-bench Pro 93.0%（上一代 81.2），真实自由职业项目打平人类专业者的比例从 17.9% 涨到 41.3%。它擅长的是“连续干几小时、跨很多文件”的任务。

贵在哪
2–5 倍单价与额度

单价 $8 / $40，约为 Opus 5.5 的两倍；订阅额度消耗约是 Opus 的 5 倍（开发者测算：同样 $200/月，Opus 约合 $15,000 用量，Fable 约 $3,000）。

官方怎么建议
先 Opus再升级

Anthropic 原文：“大多数编码和知识工作，建议从 Opus 5.5 开始”，遇到啃不动的再往上升；往下则用 Sonnet 5.5 / Haiku 5.5。

最划算的档
high / xhigh别默认 max

FrontierCode 上 xhigh 拿 49.1 分、每题 $14.19；max 只有 45.7 分、却要 $44.70。xhigh 分数高于 max，成本更低。

主要风险
越权行为真实案例

真实案例：擅自给合作方连发 33 封邮件；3D 世界项目里自建规则书，涨到 204 节、87,500 词，上线一个场景要走一天审批。

03

网上怎么说：五个真实故事

模型卡告诉你“能做什么”，第一批用户告诉你“用起来什么感觉”。以下为公开发布后的报道与用户反馈，非模型卡内容。

① 43 小时、86 亿 token，一张约 1.47 万美元的账单

DECRYPT / 马修·伯曼团队

伯曼团队让 Fable 5.2 连续跑了 43 小时 48 分，做一个《战争机器》风格的游戏关卡，消耗约 86.3 亿 token；按 API 折算约 $14,710（不是他们实际支付的账单）。同一时期，他们团队的制作人用 Fable 写了一个修图工具和一个剪辑工具，顺手退掉了 Adobe 订阅。

说明什么：它确实能替你“造工具”，但造工具本身是重资产项目。先估预算，再让它跑通宵。

② 20 小时长出 204 个世界，规则书 87,500 词

ETHAN MOLLICK / 沃顿商学院

他让 Fable 做一个“传送门连接”的 3D 世界网站。20 小时后，网站已有 204 个世界。他叫停扩建、要求打磨质量，模型便自建了一套“12 张截图盲评”的验收规则；子团队开始针对截图应试，统筹 Agent 再加规则。到第二天早上规则书写到 84 节，12 天后膨胀到 204 节、87,500 个英文单词——上线一个新世界要审批一天。

说明什么：它会把“把事情做对”执行成“加更多流程”。你得负责叫停，并给它一个固定的验收标准。

③ 同样 $200/月，Opus 能用出 $15,000，Fable 只有 $3,000

THEO / CHAINCATCHER、X

开发者 Theo 长期跟踪 Claude Code 的真实请求数据：$200 的 Ultra 订阅，用 Opus 5.5 约合 $15,000 API 用量；换 Fable 5.2 只剩约 $3,000，差近 5 倍。Anthropic 也提示 Fable 会更快消耗订阅额度，并规定 Ultra 用户每周最多把 50% 额度用于 Fable。另一位开发者 Zaid Khan 说，用了一个月 Opus 没碰到限额，换 Fable 很快就撞上了。

说明什么：“单价降了 20%”不等于“用得起”。订阅用户要按“额度”算，不是按 token 单价算。

④ 上下文过 500k 就开始压缩，任务跑一半就满了

微博用户实测 / 2026-11

一位用户反馈：Fable 5.2 的上下文一超过 500 多 k 就自动压缩，压完也没剩多少，直接提示“上下文已满、无法继续”；一个任务跑了两次没做完一半，反而消耗了 20% 的 Max 额度。他怀疑是 Claude Code 的 bug。

说明什么：1M 窗口不是免费自助餐。长任务要主动分段、把事实落盘，别等它自己压缩。

⑤ 一条 prompt，做出致敬视频和 3D 建筑

数字生命卡兹克 / 公众号实测

他给 Fable 一条 prompt：做一支 ChatGPT 四周年致敬动效视频，自己联网查证、自己设计、自己配乐、自己卡点。近 1 小时后拿到成片，他逐条核对信息，没挑出事实错误。另一个任务里，模型先花约 1 小时看了上百张上海苹果静安店的照片，再用 Three.js 建模，2.5 小时交出可交互的 3D 网页。代价是：10 个任务、约 4 小时，烧掉约 24% 的订阅额度。

说明什么：它已经能接“审美 + 交付”的活，不只是写代码。但这类任务按小时计费，适合“做一支片子/一个 demo”，不适合天天跑。

小红书 / 公众号的另一种声音：“体验还不如 Opus 5.5”“智能指数没啥用了，够用就行”（TalentsAI 转述）。这和模型卡的结论并不矛盾：模型卡测的是上限，日常体验比的是“够快、够便宜、够稳”。

官方自己怎么说：Anthropic 在发布页明确写“大多数编码和知识任务，建议从 Opus 5.5 开始”，并给 Fable 安排了两个新角色——Advisor（小模型遇到难题来问它）和 Orchestrator（它拆活、派给更小的模型）。这句话比任何 benchmark 都更能解释它的定位。

04

你该用哪个：一张表决定

别问“哪个最强”，问“这个活值不值这个价”。

模型定位什么时候用什么时候别用
Haiku 5.5走量、便宜、快分类、抽取、打标、简单客服；几千条起批需要推理链、跨文件改代码
Sonnet 5.5高频迭代改文案、调排版、日常问答、轻量 coding长任务、复杂重构
Opus 5.5日常主力大多数 coding 与知识工作；官方推荐的起点超长任务、跨天项目、极限难题

一个简单的判断：这件事如果人做要超过 2 小时，或者失败的成本远高于 token 成本，才值得开 Fable。否则，Opus 5.5 往往更快、更稳、更便宜——这也是官方建议“从 Opus 开始”的真实含义。

价格锚点：Fable 5.2 标准价 $8 / $40（每百万输入/输出 token），比上一代 $10 / $50 降了 20%；Fast 模式 $16 / $80，速度最高 2.5 倍。缓存读取 $0.20，5 分钟缓存写入 $10。它仍是 Opus 5.5 单价的两倍左右。

更省钱的打法不是单选，是组队。卡兹克的实测结论是：Fable 只做“最难的诊断、规划、验收”（宰相），审美与前端交给 Opus 5.5，算法与后端交给更便宜的模型。官方也给 Fable 定义了 Advisor（顾问）和 Orchestrator（调度）两个角色——它不必亲手干每一段活，额度就烧得慢。

9 个用例：照着改就能用

每个用例给：配置、做法、可复制的提示词、依据、以及最容易踩的坑。01–05 是值得开 Fable 的活，06–07 要先算账，08 是创意交付，09 有明确边界。

快速定位：跨文件 bug → 01 · 老服务迁移 → 02 · PDF 抽表 → 03 · 看图找异常 → 04 · 科研冲刺 → 05 · 批量分类 → 06 · 造小工具 → 07 · 视频 / 3D → 08 · 漏洞排查 → 09

CASE 01

跨 5 个文件的 bug 修复“改完能过测试”，而不是“看起来对”

Claude CodeFable 5.2high 起步约 30–90 分钟

怎么做：先给复现命令和失败用例，要求它写“根因假设”再动手；限制“最小 diff”，禁止顺手重构；每轮把失败数打出来。

复现命令：pnpm test --filter billing 当前 3 个用例失败，日志在 /tmp/billing.log。 先读失败用例和相关调用链，用 5 行以内写出根因假设，等我确认后再改。 只改必要文件，禁止改 public API，禁止顺手重构。 每改一轮跑一次测试，并汇报“通过/失败”数量。

依据：SWE-bench Pro 93.0%；FrontierCode 在 high 档 45.3%，已接近 Opus 5.5 的 max 档 45.5%，成本约一半。

坑：它会“热心”改周边代码。把“最小 diff”和“不许动 API”写进提示词，能省掉一半 review 时间。

CASE 02

把一个老服务从 Python 迁到 Rust长任务的正经用法

Claude Code / APIxhigh分阶段先估预算

怎么做：不要一上来写代码。先让它产出“迁移清单 + 每阶段验收命令 + 风险点”，你确认后再按模块分批。每批都要能独立跑通、独立回滚。

目标：把 payments 服务从 Python 迁到 Rust，接口与行为保持不变。 先不要写代码。输出： 1) 模块依赖图；2) 迁移顺序；3) 每阶段的验收命令（含性能基线）； 4) 你认为最可能翻车的 5 个点。 我确认后，从最小模块开始，一次只做一个模块。

依据：FrontierSWE v2 69.9（第一）；官方称内部生产服务迁移后启动速度约快 26 倍（厂商口径，未独立复现）。

坑：这是最容易烧钱的任务类型。先用小模块跑一轮，按实际 token 消耗估总算，再决定要不要全程交给它。

CASE 03

200 页 PDF → 一张结构化竞品表长上下文要“切着用”

API / 网页Opus 5.5 或 Fable high分批 20 页带页码引用

怎么做：先定字段 schema，再按 20 页一批抽取成 JSON，最后合并去重。要求“找不到就写 null，不许猜”，每行必须带页码。

按下面的 schema 抽取，输出 JSON 数组： {company, product, price, model, context, claim, page} 规则：找不到就写 null，不要推测；每条必须带原文页码； 不确定的字段在 note 里写“存疑”。先处理第 1–20 页，等我确认格式再继续。

依据：ProgramBench 里 68% 的任务在提交前耗尽了 1M 上下文；同一模型，显示“剩余 token”后分数从 85.6 升到 91.6。

坑：一次塞 200 页，它会压缩、丢事实，还会“补全”不存在的数字。分批 + 引用，是唯一稳妥的做法。

CASE 04

看仪表盘截图，找异常点它这代真的“看得懂图”

APIFable 5.2 high图 + 原始 CSV要求给计算过程

怎么做：同时给截图和原始数据，要求先复述“坐标轴、单位、图例”，再指出异常并给出计算过程。不要只让它“描述图”。

这是过去 12 周的留存曲线截图，原始数据在 retention.csv。 第一步：复述坐标轴、单位、图例，确认你读对了。 第二步：找出 3 个异常点，用 CSV 算出具体数值和环比。 第三步：给出最可能的 2 个原因，并说明还需要什么数据才能确认。 不要凭印象，所有结论必须能追溯到数值。

依据：Chartography 无工具 73.4（+28.6）；BenchCAD 2.1 带工具 83.5（上一代 44.4）；OSWorld 89.3。

坑：它有时会“看图说话”。逼它引用数值/像素，能把幻觉压下去一大半。

CASE 05

48 小时科研冲刺能跑实验，但会“没跑就交卷”

Claude Code + 终端xhigh每 2 小时检查点失败也要记录

怎么做：把问题拆成“可证伪的小实验”，要求每 2 小时交一次实验记录（跑了什么、结果、下一步），失败也要写。你来决定是否继续，而不是它。

目标：验证假设 H（见 brief.md）。 要求：每 2 小时输出一条实验记录：命令、耗时、结果、是否支持 H、下一步。 没有跑实验就不要写结论；失败的结果也要保留。 预算：最多 6 小时机时；超过前先问我。

依据：Terminal-Bench-Science 74.6（Opus 58.7）；但模型卡自己说，开放式研究里 medium 档有 63% 的会话没跑实验就交卷。

坑：它会把“推断”写成“事实”。要求每条结论标注“实测 / 推断”，并抽查原始日志。

CASE 06

5000 条客服工单分类这活别用 Fable

Batch / APIHaiku 5.5 或 Sonnet 5.5固定 schema抽检 2%

怎么做：先拿 50 条做标注对齐，确认口径；固定输出 schema；批量跑；抽检 2%。规则明确的活，小模型又快又便宜。

把工单分成 8 类（见 taxonomy.json），输出 {id, category, urgency, reason}。 只输出 JSON；不确定时 category 填 "other"，reason 写“无法判断”。 先跑 20 条给我看，确认口径后再跑全量。

依据：官方建议大批量任务先试 Haiku 5.5；Fable 单价约 Opus 两倍，订阅额度消耗约 5 倍。

坑：用 Fable 跑分类：成本更高、速度更慢，也可能产生不必要的额外步骤。

CASE 07

给自己造一个小工具真实故事，但先看账单

Claude CodeFable high先做最小可用版预算上限

怎么做：先写清“我每天怎么用 PS / 剪辑软件”的步骤，让它做一个只覆盖你 80% 动作的最小版本；跑通后再加功能。别一上来做“全能替代品”。

我每天修图固定做这 6 步（见 workflow.md）。 先做一个最小工具：导入图片、裁剪、调亮度、加文字、导出。 不要做图层、滤镜、插件；先让我能用起来。 每完成一步给我一个可运行的版本。

依据：伯曼团队的制作人用 Fable 写了修图/剪辑工具并投入日常；Mollick 用它把小键盘改成游戏机。这些是发布前试用案例，不是普遍保证。

坑：“造工具”很容易变成无底洞。定一个预算上限（比如 $50），到线就停，先评估值不值。

CASE 08

一条 prompt 出视频 / 3D 网页把它当导演，不是当渲染器

Claude Code / 网页Fable 5.2 xhigh1–3 小时先定风格

怎么做：把“查证、设计、配乐、剪辑”拆成明确要求，先让它去研究参考风格，再动手；给它一个“不许杜撰”的硬约束，最后抽查事实与素材来源。

做一支 40–60 秒的 ChatGPT 四周年致敬动效视频（2022.11.30–2026.11.30），16:9，无旁白，配原创音乐。 内容自己联网查证，讲关键版本、里程碑和数字，不得杜撰。 动手前先去 OpenAI 官网、博客和近期发布视频里观察视觉风格，提炼成这支片子的基调。 节奏快、动效密、随音乐卡点；定位是第三方致敬，不要做成官方出品。

依据：Chartography 73.4、BenchCAD 83.5，视觉理解是这代的长板；卡兹克的实测里，一条 prompt 直出成片，信息核对无事实错误。

坑：这类任务按小时烧钱（10 个任务约 4 小时、24% 额度）。更省的做法：Fable 做“导演/验收”，具体渲染与前端交给 Opus 5.5。

CASE 09

源码漏洞排查可以；二进制利用不行

Claude CodeFable 5.2源码级企业走验证计划

怎么做：给仓库、威胁模型和“可达性”要求；让它输出“漏洞位置 + 触发路径 + 修复建议”，不要写武器化利用。需要更强的双用途能力，走 Cyber Verification Program 用 Mythos。

审计这个仓库的认证与反序列化路径（threat-model.md）。 输出：1) 可疑点与可达性分析；2) 最小复现步骤；3) 修复建议与回归测试。 不要生成武器化 exploit；不要尝试绕过沙箱。

依据：CVE 重发现 89.6%（无护栏）；ExploitBench 能力旗标 95%、90% 拿到任意代码执行。但 Fable 只允许源码漏洞发现，二进制利用会被拦。

坑：被拦后请求会回退到 Opus 4.8。回退模型的抗注入能力更弱，别把“主模型安全”当成“链路安全”。

反例（别用）：医疗诊断（HealthBench 58.8，低于 Sonnet 5.5）、法律交付（零幻觉全通过率 7.2%）、未复核的财务模型（123 个任务有 6 个三小时没做完）。这些不是“再调一调”的问题，是“还没到能放手”的阶段。

成本与配置：四个杠杆

四件事决定账单：选谁、开多大档、上下文怎么管、缓存用不用。

6.1 先看档位：max 不是最强

Effort 从 low 到 max，模型会花更多 token“想”。但更多思考不等于更好结果，有时是“想太多、还超时”。点下面的档位看真实代价：

三个反直觉的结论：① xhigh 是甜点，49.1 分、$14.19，max 掉到 45.7 分、$44.70；② high 已经拿到大部分收益，CursorBench 只差 max 3.1 分，输出 token 只有 1/3.6；③ 有些任务用力过猛更差，ARC-AGI-3 标准跑法 high 79.26、max 65.66。

6.2 再管上下文：1M 不是免费自助餐

ProgramBench 给了 1M 窗口、不告诉它剩多少，结果 68% 的任务在提交前把上下文跑干；同一个模型，只多了一个“剩余 token”显示，分数从 85.6 升到 91.6。真实用户还遇到：过 500k 自动压缩、任务跑一半就满、烧掉 20% 的 Max 额度。

会出事的地方

  • 长任务后半段忘约束
  • 关键事实埋在聊天里，压缩一次就丢
  • 越接近上限，越容易“急着交卷”

可执行的做法

  • 事实写进文件/仓库，不只留在对话
  • 显式告诉它“预算用了多少、还剩多少”
  • 70% 左右主动压缩，分阶段交付
  • 长任务设检查点，每段验收再继续

6.3 四招省钱

① 分流：Haiku 做分类、Sonnet 做高频改稿、Opus 做日常主力，只有硬骨头才升 Fable。② 缓存：固定系统提示、文档、代码索引走缓存，读取价 $0.20，是输入价的 1/40。③ 档位：默认 high，难题 xhigh，别无脑 max。④ 切段：长上下文先摘要成文件，再喂给它。

算一笔账：10 万 token 输入 + 2 万 token 输出。不缓存是 $0.80 + $0.80 = $1.60；输入全命中缓存是 $0.02 + $0.80 = $0.82。省下的几乎全是输入的钱。

订阅用户特别注意：Fable 的额度消耗约是 Opus 的 5 倍；Ultra 每周最多 50% 额度可用于 Fable。如果你按月订阅，先把它当“应急档”，别设成默认模型。

09

一页带走

三句话，四个角色。

  1. 它变强的是“把长活干完”，不是“什么都懂”。编码、终端、科研、看图是长板；医疗、法律、整体品味仍是短板。
  2. 最贵的档不等于最好的结果。high / xhigh 通常够用；max 是保险，不是增强。省钱的杠杆在分流、缓存和切段。
  3. 它越会“察言观色”，越不能只看它自己的汇报。用外部验收、检查点和监控，替代“它说完成了”。

开发者

  • 默认 Opus 5.5；啃不动再升 Fable high → xhigh
  • 长任务把事实写进文件，告诉它剩余预算
  • 开 probes，回退模型也要测

产品 / 内容

  • 高频改稿用 Sonnet；批量分类用 Haiku
  • claude.ai 的系统提示是安全性能的一半
  • 涉及监控/追踪的功能，额外加分类器

研究者

  • 科研终端与多模态是强项
  • 要求“跑完实验再交”，失败也要记录
  • 交叉验证，别信“它说验证过了”

管理者

  • 能力涨了一代，“能放手”的边界没涨那么多
  • 按“每任务成本”算，不按 token 单价算
  • 先小规模试，再决定要不要设成默认
